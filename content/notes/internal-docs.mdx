# Ecosystem Architecture

## Full stack

```
Developer / AI Agent
        │
   kranix-cli  |  kranix-mcp
        │
   kranix-api          ← REST/gRPC, auth, audit, SSE
        │
   kranix-core         ← reconcile, schedule, policy, events
        │
   ┌────┼────────────┐
   ▼    ▼            ▼
runtime  operator   packages
   │
Docker · K8s · Remote nodes
```

## Layer responsibilities

| Layer | Repo | Does |
|-------|------|------|
| Portal | kranix-web | This site — docs & workspace UI |
| Clients | kranix-cli, kranix-mcp | Humans and AI agents |
| API | kranix-api | Front door — no business logic |
| Core | kranix-core | Brain — reconciliation & state |
| Runtime | kranix-runtime | Infra drivers |
| GitOps | kranix-operator | CRD reconciliation from Git |
| Shared | kranix-packages | Types, mock API |

## Desired state sources (core)

1. Git — `KranixApp` manifests
2. API — deploy/update from CLI
3. AI — MCP tool calls (audited, scoped)

## Design principles

1. CLI ≡ API ≡ MCP (same capabilities, different surfaces)
2. Git is source of truth for declared workloads
3. Core never speaks HTTP; API never schedules workloads
4. Composable — run MCP-only or drivers without full K8s stack
