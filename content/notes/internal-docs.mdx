# Ecosystem Architecture

## Full stack

```
Developer / AI Agent
        │
   kranix-cli  |  kranix-mcp
        │
   kranix-api          ← REST/gRPC, auth, audit, SSE
        │
   kranix-core         ← reconcile, schedule, policy, events
        │
   ┌────┼────────────┐
   ▼    ▼            ▼
runtime  operator   packages
   │
Docker · K8s · Podman · Remote · Compose
```

## Data flow

1. **Intent** enters via Git (`KranixApp`), CLI (`kranix deploy`), or MCP (`deploy_workload`)
2. **kranix-api** authenticates, validates, audits
3. **kranix-core** reconciles desired vs actual state on the event bus
4. **kranix-runtime** or **kranix-operator** applies changes to infrastructure
5. Status and events stream back through API → CLI/MCP/SSE

## Design principles

1. CLI ≡ API ≡ MCP (same capabilities, different surfaces)
2. Git is source of truth for declared workloads (with API/AI overlay)
3. Core never speaks HTTP; API never schedules workloads; runtime never exposes HTTP
4. Composable — mock API, MCP-only, drivers without full stack
