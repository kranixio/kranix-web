# kranix-core

> The orchestration engine — state, scheduling, and reconciliation for the Kranix platform.

`kranix-core` owns all business logic. Nothing touches Docker or Kubernetes directly except through **kranix-runtime**, driven by core.

## Architecture position

```
kranix-api  ──►  kranix-core  ──►  kranix-runtime
                    │
                    ├──►  kranix-operator
                    └──►  kranix-packages
```

## Reconciliation loop

```
Observe  →  Compare to desired  →  Diff  →  Apply  →  repeat
```

Desired state merges from **Git** (`KranixApp` CRDs), **API** (`POST /deploy`), and **AI** (MCP agent actions).

## Workload capabilities

- **Cron scheduling** — standard five-field cron, optional timezone, concurrency policies
- **Priority & preemption** — `critical` | `high` | `normal` | `low` scheduling tiers
- **Resource quotas** — per-namespace or per-team hard limits on CPU, memory, workload count
- **Drift detection** — alerts when runtime diverges from declared spec
- **Event sourcing** — immutable log of every state transition
- **Health gates** — block rollouts until HTTP/TCP/Prometheus checks pass
- **Circuit breaker & warm standby** — failover to a linked standby workload
- **Rollback history** — versioned spec snapshots for instant revert

## Event bus

Internal components communicate via typed events, for example:

```
WorkloadDeployRequested → WorkloadScheduled → WorkloadRunning | WorkloadFailed
```
